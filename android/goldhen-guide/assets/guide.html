GoldHEN Jailbreak Guide

PSFree + Lapse on firmware 9.00 (no USB stick needed)

Date: 31 Oct 2026 (Australia/Perth)
Console: PS4, firmware 9.00
Method: PSFree (browser) + Lapse (kernel) + GoldHEN
Not this guide: exfathax USB, Vue Extended Storage, PPPwn

Read this on your phone. Follow the numbered steps. If something fails, jump to Troubleshooting before looking at Troubleshooting.

Quick words (so nothing is scary)

Word Plain meaning
Jailbreak / HEN Temporary unlock. Lets GoldHEN run. Gone after a full power-off unless you use Rest Mode.
GoldHEN The home menu tool that appears after a successful jailbreak.
PSFree The browser exploit (the page that runs in the PS4 web browser).
Lapse The kernel exploit that comes after PSFree. No USB image.
WebKitty The nice web page that packages PSFree + Lapse + GoldHEN for you.
Host / server Your phone or PC serving that page over Wi‑Fi on port 8081.
Cache The PS4 browser saving the page files so you can jailbreak again with less (or no) help from the phone.
Rest Mode Sleep. Keep "Keep Application Suspended" on so GoldHEN often survives sleep. Full power-off needs another jailbreak.

A. What you need

  1. PS4 Slim on firmware 9.00 (do not update).
  2. Same Wi‑Fi for the PS4 and your phone/PC (the host).
  3. One of these hosts (pick one):
  4. Android phone with Termux (easiest to carry) — recommended.
  5. Any laptop/PC that can run Python 3 (Windows, Mac, or Linux).
  6. The WebKitty folder (see section B) on the host phone or PC.
  7. No special USB stick for this method. Leave any old exfathax stick unplugged.

Optional but smart: - A charger for the phone so Termux stays alive. - Screenshot this cheat sheet (section I) onto your phone.

B. One-time: get the WebKitty files onto your phone or PC

You only do this once (or when you update the host zip).

Option 1 — Pack a USB / zip of the host files

The zip should contain both:

  • webkitty/ — the full WebKitty site (~12 MB)
  • server-webkitty.py — tiny Python script that serves it on port 8081

On the build machine those are the WebKitty site folder and its Python server script.

Pack it like this:

cd /path/to/webkitty-host
zip -r ~/webkitty-8081.zip server-webkitty.py webkitty

Then copy webkitty-8081.zip to the Android phone (USB, Syncthing, AirDrop, Drive, or similar).

On the Android phone (Termux), after the zip is on the phone:

# Install unzip + python if needed (one-time)
pkg update -y
pkg install -y python unzip

# Put the zip somewhere Termux can see it, then:
mkdir -p ~/ps4
cd ~/ps4
unzip -o /path/to/webkitty-8081.zip
# You should now have:
#   ~/ps4/server-webkitty.py
#   ~/ps4/webkitty/   (with index.html inside)
ls server-webkitty.py webkitty/index.html

Tip: If you use a file manager app, copy the zip into Termux home with something like
cp /sdcard/Download/webkitty-8081.zip ~/ps4/ then unzip there.

On a PC instead of a phone:

  1. Unzip so you have server-webkitty.py and webkitty/ next to each other in one folder.
  2. Open a terminal in that folder.
  3. Run: python3 server-webkitty.py (Windows: python server-webkitty.py).
  4. Leave that window open. Note the PC's Wi‑Fi IP (see section C step 6).

Option 2 — Download WebKitty yourself (if you have no zip)

Only if the packed zip is missing and you have internet on the host device:

# In Termux or on a PC with git + python
pkg install -y git python   # Termux; skip on PC if already installed
mkdir -p ~/ps4 && cd ~/ps4
git clone https://github.com/ArabPixel/WebKitty.git webkitty

Then create server-webkitty.py next to the webkitty folder with this exact content:

import http.server, socketserver, os
os.chdir(os.path.join(os.path.dirname(os.path.abspath(__file__)), 'webkitty'))
class H(http.server.SimpleHTTPRequestHandler):
    extensions_map = {**http.server.SimpleHTTPRequestHandler.extensions_map,
        '.manifest':'text/cache-manifest', '.mjs':'text/javascript',
        '.js':'text/javascript', '.bin':'application/octet-stream'}
    def end_headers(self):
        self.send_header('Cache-Control','no-cache'); super().end_headers()
socketserver.ThreadingTCPServer.allow_reuse_address=True
with socketserver.ThreadingTCPServer(('0.0.0.0',8081),H) as s: s.serve_forever()

Save it as ~/ps4/server-webkitty.py.

What NOT to use

  • Do not use the older Nazky page on port 8080. That is a different site. If you ever see an error like "This only works when hosted as a local server" on a Nazky-looking page, you are on the wrong host. Close it and use :8081 WebKitty instead.
  • Do not open https:// GitHub pages on the PS4 browser. The PS4 often shows "cannot communicate via SSL". Always use plain http:// to a local IP.

C. Phone Termux host — start the server every time you need it

Do this whenever the PS4 needs a fresh jailbreak and the cache alone is not enough (see section H).

  1. Connect the phone to the same Wi‑Fi as the PS4.
  2. Open Termux.
  3. Keep the phone awake for the jailbreak:
termux-wake-lock
  1. Go to the folder:
cd ~/ps4
  1. Start the server:
python server-webkitty.py
  • You should see almost nothing (it just sits there). That means it is running.
  • Leave Termux open. Do not swipe it away.

  • Optional background start: nohup python server-webkitty.py &
    Stop later with: pkill -f server-webkitty.py

  • Find your phone's Wi‑Fi IP address:

  • Phone Settings → Wi‑Fi → tap your network → look for IP address
    (example: 192.168.1.42 — yours will differ at home).
  • Or in Termux:
ifconfig 2>/dev/null | grep -A1 wlan || ip addr show wlan0
  1. On the phone browser, smoke-test:
http://localhost:8081/

You should see the WebKitty page. If not, the server is not running or the files are in the wrong place.

  1. Write down (or screenshot):
http://YOUR_PHONE_IP:8081/

Example shape: http://192.168.1.42:8081/

"Address already in use"

An old Python server is still running. Fix:

pkill -f server-webkitty.py
# or force-close Termux fully, reopen, then cd ~/ps4 && python server-webkitty.py

D. PS4 network setup (block updates)

Sony can brick the jailbreak path with a system update. Block updates.

Which network? Option A (best): spare offline router

Use a spare offline router, with no internet:

  1. Factory-reset it.
  2. Join its default Wi‑Fi from the sticker.
  3. Open http://192.168.10.1 (or the address on the sticker).
  4. Set a Wi‑Fi name and password. Skip the internet step. Leave AdGuard off.
  5. Connect the phone/Nexus that hosts the server and the PS4 to it.

The PS4 internet connection test will fail. That is fine.

Never set this router up on the home network: it uses the same IP (192.168.10.1) as the home router and will clash.

Option B (backup): phone hotspot

Turn on the hotspot and connect the host phone and the PS4 to it. The DNS steps below apply to both options.

Path D1 — Use public update-block DNS (recommended if you stay online)

  1. On the PS4: Settings → Network → Set Up Internet Connection.
  2. Choose your Wi‑Fi → Custom.
  3. IP Address Settings: Automatic (unless you know you need Manual).
  4. DHCP Host Name: Do Not Specify.
  5. DNS Settings: Manual.
  6. Enter:
  7. Primary DNS: 165.227.83.145
  8. Secondary DNS: 192.241.221.79
    (These are the well-known Al‑Azif PS4 update-block DNS servers.)
    If those don't work, try Modded Warfare's hosts: 45.56.67.85 or 62.210.38.117.
  9. MTU: Automatic. Proxy: Do Not Use.
  10. Test Internet Connection. It can say "Internet: Failed" for some checks and still be fine for the local host — what matters is the PS4 is on the same Wi‑Fi as the phone and can open http://PHONE_IP:8081/.

Path D2 — Stay offline after the first successful cache

  1. First jailbreak while the phone host is on (sections E + H).
  2. After the page has cached to 100% and you have jailbroken successfully once, you can turn the PS4 network off for day-to-day use and still re-run from the browser cache (see H).
  3. Trade-off: some features need LAN; for a pure offline box this is fine.

Path D3 — If you later get a home AdGuard / Pi-hole

Point Primary DNS at that box's LAN IP. Until then, use D1 or D2.

Never do this

  • Do not sign into PSN on this console.
  • Do not accept a System Software Update.
  • Do not use Safe Mode "Update System Software" unless you intend to leave 9.00.

E. First jailbreak (the real run)

Phone server must already be running (section C). PS4 on same Wi‑Fi.

  1. On the PS4, open the Internet Browser
    (the normal browser app — not "User's Guide", not Settings help).
  2. In the address bar type exactly (use http, your phone IP, port 8081):
http://YOUR_PHONE_IP:8081/
  1. Wait. The page should load WebKitty (title / logo says WebKitty).
  2. Let it cache. Watch for a progress indicator / checkmark. Wait until it reaches 100% or shows that caching finished.
    First time can take a minute. Be patient. Do not spam the button yet.
  3. Press the OPTIONS button on the controller → choose Refresh (reload the page once).
  4. On the WebKitty screen:
  5. Exploit / chain: choose PSFree with Lapse (often labelled like "PSFree Lapse", Modular or Bundle — either is fine on 9.00).
  6. Payload / HEN: choose GoldHEN.
  7. Tap Start (or the main jailbreak button).
  8. Wait. Do not leave the page. You may see status text. Success usually ends with a GoldHEN notification / toast on screen.
  9. Hold the browser Back button (or close the browser) and return to the home screen. GoldHEN should appear on the home row / as a running tool.
  10. You are jailbroken for this power cycle. Put the console in Rest Mode when you stop playing (see G) so you do not have to redo this every short break.

First-time tip if a PC host is already on the same Wi‑Fi

You can do steps E1–E10 once using a PC host on the same LAN:

http://YOUR_PC_IP:8081/

(WebKitty on a PC on the same LAN). Afterwards you only need the phone when the cache is missing or after a full power-off without cache. Still pack the phone host — do not rely on a remote PC once you are at your own house.

F. Troubleshooting

"Cannot communicate via SSL" / SSL error

You opened an https:// page. The PS4 browser hates many HTTPS hosts.

  • Fix: use http:// and a local IP (192.168.… or 10.…), never https://github… or random HTTPS mirrors.
  • Correct shape: http://192.168.x.x:8081/

"This only works when hosted as a local server" (Nazky / :8080 page)

You are on the wrong page (old Nazky PSFree on port 8080).

  • Fix: close it. Open http://YOUR_PHONE_IP:8081/ (WebKitty).
  • Never use :8080 for this Lapse guide.

"Not enough memory"

Common and usually harmless.

  1. Press OK.
  2. Tap Start again.
  3. If it repeats many times: leave the browser with Back, reopen the same URL, Refresh once, Start again.

Page stuck / spinner forever

  1. Press Back.
  2. Open the same http://…:8081/ again.
  3. OPTIONS → Refresh.
  4. Start again.

Black screen / freeze / no response

  1. Hold the PS4 power button until it fully shuts down (beeps, then off). Wait 20 seconds.
  2. Power on.
  3. Start the phone server again if needed.
  4. Retry from section E.

Phone IP changed / page will not load

Routers often give the phone a new IP after reboot.

  1. Re-check the phone Wi‑Fi IP (section C step 6).
  2. Update the URL on the PS4.
  3. Confirm http://localhost:8081/ still works on the phone.

WebKitty loads but Start does nothing

  • Confirm firmware is still 9.00 (Settings → System → System Information).
  • Confirm you picked PSFree + Lapse and GoldHEN.
  • Try the other PSFree Lapse style (Modular ↔ Bundle) if both appear.
  • Fully close the browser, reopen, Refresh, Start.

Termux "python: command not found"

pkg update -y
pkg install -y python

Firewall on a Windows PC host

Allow Python on private networks, or temporarily allow inbound TCP port 8081, or the PS4 cannot reach the PC.

G. After success — daily habits

  1. Rest Mode tip
    Enable Rest Mode and turn on "Keep Application Suspended" (wording may vary slightly). GoldHEN often survives Rest Mode. A full power-off usually needs another browser run.
  2. Never sign into PSN on this console.
  3. Never system-update. Keep the update-block DNS (D1) or stay offline (D2).
  4. No special USB for Lapse. You do not insert an exfathax stick. If you still own one, leave it unplugged — plugging it at the wrong time can crash a boot.
  5. GoldHEN settings (optional later): inside GoldHEN you can toggle debug settings, bin loader, etc. You do not need any of that for a basic jailbreak.
  6. If GoldHEN is missing after a full shutdown, just repeat section E (often faster once cached — see H).

H. Offline / after the first cache — when do you need the phone again?

How caching works (simple)

The first time WebKitty loads, the PS4 browser downloads and stores the exploit files for your firmware (firmware-based caching). When that finishes at 100%, later visits can reuse those files.

Practical rules

Situation Need phone server?
First ever jailbreak Yes — phone (or a PC on the same LAN) must serve the page.
Full power-off, cache still present, same URL bookmarked Often no — open the browser bookmark / history entry and run again. If it fails, start the phone.
Cleared browser cookies/data / "rebuild database" / new user Yes — cache is gone.
Phone off Wi‑Fi but cache warm Try the browser alone; if the page is blank or incomplete, start the phone.
You changed Wi‑Fi and the old IP is bookmarked Update the bookmark to the new http://NEW_IP:8081/ or use history after one good load.

Make a bookmark after the first good load

  1. After WebKitty loads successfully once, use the browser menu to Add to Bookmarks.
  2. Name it WebKitty or Jailbreak.
  3. Next time: open the bookmark → wait/cache if needed → Refresh → GoldHEN → Start.

When the phone is required again

  • Cache cleared or corrupt.
  • WebKitty files updated (re-copy the zip and re-cache).
  • Bookmark points at a dead IP and you have no working history entry.

Keep the Termux setup forever. It is your safety net.
